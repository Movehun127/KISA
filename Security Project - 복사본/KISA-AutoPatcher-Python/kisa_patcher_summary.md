# 🛡️ KISA Windows 보안 패치 프로젝트 작업 및 개선 요약

본 문서는 KISA Windows 보안 취약점 조치기 프로그램(`KISA-AutoPatcher-v2`) 개발 및 유지보수 과정에서 수행한 핵심 수정 사안과 아키텍처적 개선 내용을 정리한 요약본입니다. 타 생성형 AI(Gemini 등) 모델에 문맥을 전달하거나 전체 히스토리를 요약하기 위한 자료로 활용하실 수 있습니다.

---

## 1. ⚙️ 프로젝트 아키텍처 개요
* **언어 및 플랫폼**: Python 3.x, Windows OS
* **주요 엔진 구성**:
  - `main.py`: Tkinter 기반 GUI 구동 및 진단/조치 오케스트레이션
  - `core/detector.py`: 각 취약점 코드의 정책 기준 충족 여부 검사 (Registry, Secedit, PowerShell 기반)
  - `core/remediator.py`: 취약 판정 시 자동 패치 적용 및 롤백 기능 지원
  - `core/capturer.py`: Windows UIAutomation 기반으로 실제 해당 정책의 설정창(`secpol.msc`, `services.msc`, `ncpa.cpl` 등)을 실행 및 탐색하여 증빙용 스크린샷 캡처
  - `core/reporter.py`: 조치 완료 시 최종 취약점 보고서 생성 (Markdown 및 Excel 모델화 양식)

---

## 2. 🛠️ 주요 수정 및 개선 사항

### ① W-05 / W-09 오탐 개선 및 조치 스크립트 고도화
* **오탐 원인**: 정책 레지스트리 값이 명시적으로 설정되지 않고 윈도우 기본값(양호 수준)일 때, 단순 파싱 실패로 인해 "취약"으로 강제 진단되는 버그 존재.
* **해결 내용**:
  - Null 및 빈 값 파싱 예외 처리를 정교화하여 기본값일 때 올바르게 "양호" 판정이 나도록 보완.
  - 음수 값(-1 등)까지 안전하게 추출할 수 있도록 정규식 패턴을 `(-?\d+)` 형태로 개선.
  - `net accounts` 명령어로 반영되지 않는 로컬 정책 영역을 `secedit` 보안 템플릿 임포트 기법을 사용하는 강력한 PowerShell 스크립트로 대체하여 조치율 100% 달성.

### ② Skip/양호 항목 증빙 캡처 강제화
* **개선 요구사항**: 이미 "양호"하거나 캡처 전용("Skip") 설정된 항목도 감사 제출용 증빙자료 수집을 위해 설정 화면을 띄워 캡처해야 함.
* **해결 내용**: `core/capturer.py`에서 기존에 `captureOnly` 또는 `is_status_safe`일 경우 스킵하던 팝업 탐색 방기 조건을 제거하여, 상태값과 상관없이 동일하게 해당 설정창을 열고 트리 구조를 탐색하여 포커스 후 스크린샷을 찍도록 조정.

### ③ MMC 콘솔(`.msc`) UIA 탐색 속도 최적화
* **현상**: `secpol.msc` 등 대형 목록에서 키보드 방향키 가속을 내릴 때 윈도우 UI 스레드가 포커스를 미처 갱신하지 못해 목록의 중간 단계에서 "바닥 도달"로 오판하고 탐색이 종료되던 현상.
* **해결 내용**: 키보드 입력 전송 딜레이 타임을 최소 `0.1s` 이상으로 상향 확보하여 UI 렌더링 스레드가 가속을 완전히 따라갈 수 있도록 안정화.

### ④ W-18 하드코딩 제거 및 범용 데이터 기반 멀티 캡처 구현
* **현상**: 불필요한 서비스 제거 항목(W-18)에서 `CryptSvc`, `Dhcp`, `Dnscache` 등 종료할 수 없는 Windows 핵심 시스템 필수 서비스가 타겟에 묶여 있어 조치가 무조건 실패하던 문제.
* **해결 내용 (범용 아키텍처 개편)**:
  - **JSON 데이터 구조화**: 필수 서비스는 제외하고 `Distributed Link Tracking Client`, `Print Spooler`, `Remote Registry`, `Cryptographic Services` 4종만 남김.
  - **하드코딩 완전 제거**: 파이썬 코어 코드(`capturer.py` 등)에서 특정 취약점 코드(`W-18`) 분기를 없애고, JSON 내 `"multiCapture": true`와 `"targetServices"` 속성을 직접 읽어 루프를 돌리는 **완전 범용 데이터 기반(Data-Driven) 정책 엔진**으로 전환.
  - **순차 멀티 캡처 구현**: 4개 대상 서비스의 한글/영문 DisplayName 매핑에 맞추어 `services.msc` 기동 ➔ 해당 서비스 포커싱 ➔ 속성창 팝업 ➔ 각각 개별 캡처(`W-18_TrkWks.png`, `W-18_Spooler.png` 등) 후 종료하는 루프형 UIA 시퀀스를 구현.

### ⑤ W-20 NetBIOS 바인딩 서비스 정탐 진단 검증
* **현상**: 사용자가 W-20 항목을 이미 조치했다고 인지하였으나, 여전히 "취약"으로 스캔됨.
* **원인 분석**: 사용자의 유선 랜 카드(Ethernet) 설정은 정상 조치(비활성화)되었으나, 무선 랜 카드(Wi-Fi, Intel AX201) 설정이 여전히 Default(0, 취약 상태)로 남아있었음.
* **결과**: 진단 스캐너가 다중 활성 어댑터 중 미흡한 위협 요소를 정밀하게 정탐하고 있음을 입증하고, 해결을 위해 어댑터 일괄 조치 가이드 제시.

### ⑥ 레지스트리 편집기(regedit) 한글 IME 간섭 이동 실패 오동작 해결
* **현상**: 레지스트리 캡처 정책들이 주소창에 경로를 직접 타이핑할 때, 사용자 PC의 한글 IME 입력기 활성화 상태에 따라 문자가 자음/모음으로 조합되어 경로가 깨져서 항상 동일한 이전 경로가 캡처되는 문제.
* **해결 내용**: 키보드 타이핑 방식을 폐기하고, Windows API를 이용해 클립보드 메모리에 다이렉트로 유니코드 데이터를 적재한 후 `Ctrl + V`로 붙여넣는 방식으로 리팩토링하여 IME 언어 상태와 무관하게 100% 신뢰성 있는 경로 이동 보장.

## 3. 📝 향후 유지보수를 위한 Tip
1. **정책 변경 방식**: 새로운 취약점 정책이나 검사 기준이 생길 경우, 파이썬 소스코드를 건드릴 필요 없이 `config/policies/` 폴더 내부의 JSON 템플릿 파일 규격만 확장/수정하면 됩니다.
2. **PyInstaller 빌드 동기화**: 정책 설정(`.json`)을 변경한 경우 반드시 `Copy-Item -Recurse -Force` 등을 실행하여 `dist/config/policies` 폴더 안의 실제 JSON들을 갱신한 후 PyInstaller 빌드를 진행해야 배포판 파일에 정상 반영됩니다.
